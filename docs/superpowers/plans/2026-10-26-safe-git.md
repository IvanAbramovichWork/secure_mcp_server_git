# Safe Git MCP implementation plan

Goal: implement docs/SPEC.md using synthetic repositories only. Never access ECSS10.
Architecture: immutable startup binding -> bounded fixed Git commands -> centralized path authorization -> typed constructed responses -> official MCP v2 stdio.
Tech stack: Python >=3.11, MCP >=2.3,<3, Pydantic, pytest, uv locked dependencies.

Global constraints: read-only; no shell commands from clients; no unfiltered errors or metadata; deny by default on ambiguity; local mode has no OS confidentiality guarantee.

1. Policy/config: write denial and glob semantics tests, run RED, implement validated TOML and pure Git-path policy, run GREEN.
2. Backend/refs: synthetic fixtures; write ref/injection/startup/limits tests, run RED, implement subprocess isolation and immutable binding, run GREEN.
3. History: write filtered mixed/root/merge and adversarial tests, run RED; implement log/history, then approved-path-only patches; run GREEN.
4. MCP: write official-client stdio tests including invalid inputs and fake-secret non-disclosure; run RED; register strongly typed tools, run GREEN.
5. Documentation/CI: sample policy, deployment and threat model, separate hardening plan; lint, mypy, complete pytest suite; independent review and regression fixes.

Review focus: Git-local configuration and replace/alternates; literal unusual paths; parser failure with no partial output; aggregate request resource limits; metadata/provenance residual disclosure.
Execution: inline, authorized by user's explicit implementation request. Existing isolated cloud checkout on unborn work branch; no worktree required. Advanced tools will use the same security boundary. No production deployment or real repository validation is authorized.
