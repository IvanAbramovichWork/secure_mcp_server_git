# Docker deployment plan

Provide a Linux OCI image for the existing stdio server. Keep all MCP security rules and single-repository binding unchanged. Do not inspect ECSS10.

1. Write real Docker integration tests first using generated fake-secret repositories: official SDK stdio request filtered correctly; read-only mounts, non-root UID/capabilities/network enforcement; linked-worktree diagnostic; no protected sentinel in responses.
2. Build a multi-stage image from an official Python image pinned to its pulled digest, install runtime Git/util-linux and locked production Python dependencies. Whitelist Docker context files. Default non-root user; operator overrides UID:GID to match mounted repository ownership. No credentials or original repositories in image.
3. Run integration tests against the built image with read-only root/repo/policy, no network, capabilities dropped, no-new-privileges, tmpfs /tmp, memory/CPU/PID limits. Fix Docker compatibility issues without loosening backend checks. Document honest runtime blockers if any.
4. Add CI image build and Docker integration checks, clear Docker/Claude run instructions, synthetic demo creation, per-project containers and security limitations. Dockerizing this service does not isolate a host-side agent or implement the privileged broker. Linked worktrees remain unsupported.
5. Review, run full suite/lint/type/build checks and publish changes to GitHub.

## Results

- Three initial container tests failed without an image; image built with verified official base digest and locked production packages. Five real-image tests now pass.
- Cloud build DNS required supported proxy routing and optional build-only CA trust; APT CA mount readable by its downloader. No TLS/checksum/signature bypass.
- Fresh review requested explicit default-user and doctor success checks, plus recursive read-only bind behavior. Added those checks and fail-closed recursive/rprivate flags.
- Regression caught Docker client auto-injected runtime proxies; explicit runtime env clearing fixed it. Build-only CA/proxy data is absent from image configuration/runtime mounts.
- Final suite with Docker enabled: 132 passed, zero skips. Lint/format/type checks and package builds passed. No real ECSS10 access, linked-worktree support, registry push, privileged broker or whole-agent isolation claim.
